# 05. File, thư mục, an toàn

1. **Không sửa trực tiếp thư mục `DoAnMonHoc/Final` (của anh bạn).** Nếu cần sửa, sao lưu bản gốc trước vào `_backup_truoc_khi_sua`. Ưu tiên tạo file mới trong dự án này.
2. **Không xóa file của An** khi chưa được cho phép rõ ràng. Cần xóa thì xin quyền một lần cho đúng thư mục cần, hoặc chuyển vào thư mục `_to_delete/` rồi báo An.
3. **File Word đang mở sẽ bị khóa** (có file `~$...`). Không ghi đè; lưu tên mới (ví dụ thêm `_da_sua`) và báo An.
4. Giữ nguyên bản gốc của bài báo và dữ liệu tải về. Làm việc trên bản sao.
5. Cấu trúc thư mục dự án:
   - `Bai_bao_Survey/`: bài báo (không đổi tên file đã đánh số).
   - `Tom_tat_bai_bao/`: 40 file tóm tắt và mục lục chọn 20 bài.
   - `docs/`: kế hoạch, đánh giá, ghi chú.
   - `code/`: script thực nghiệm (tạo khi tới giai đoạn thực nghiệm).
   - `results/`: file CSV kết quả, hình.
   - `reports/`: báo cáo giữa kỳ, cuối kỳ, slide.
6. Tên file không dấu, dùng gạch dưới, có số thứ tự khi cần.
7. Tải dữ liệu hoặc code từ nguồn chính thức (OpenML, kho GitHub của tác giả). Ghi lại URL, ngày tải, phiên bản hoặc mã commit.
8. Môi trường chạy có thể chỉ cho phép mạng tới kho gói và GitHub. Nếu yêu cầu bị chặn, nói rõ và nhờ An tải file; không cố vòng qua.
9. Không đưa thông tin cá nhân của An (mật khẩu, tài khoản) vào file dự án.
